## 비루트 80 — 아무것도 안 붙이는 쪽을 골랐다
도커가 컨테이너마다 `net.ipv4.ip_unprivileged_port_start=0` 을 기본으로 넣는다. 실측: 그 값 `0` ·
`CapEff=0000000000000000` 인데 `bind(0.0.0.0:80)` **성공**(uid 10001). 즉 `CAP_NET_BIND_SERVICE` 로 되는 게 아니다.
버린 대안 — `cap_add`(비루트면 유효셋이 비어 무효) · `setcap`(인터프리터에 영구 특권, 재설치 때 소실) ·
sysctl 명시(현 값과 중복. 단 구버전 도커·k8s 로 옮기면 이걸 명시해야 한다) · 루트 실행(금지).

## 리뷰어에게
- **교체 전제가 깨졌다.** 별칭은 살아도 포트가 달라져 `http://crawler-web:42030` 은 교체 순간 연결 거부다.
  cutover 의 "설정 한 글자도 안 고친다" 는 이제 거짓 — 두 파일에 경고를 박고 C1~C5 를 선행조건으로 걸었다. **롤백도 짝을 맞춰야 한다.**
- **지시 범위를 둘 넘었다.** (a) thread·delegate 공용망 연결 — 안 하면 부르는 쪽이 서비스명으로 못 닿고 지시된 검증 명령 자체가 성립하지 않는다.
  (b) compose 서비스키 개명 — 사용자가 정한 서비스명과 DNS 이름을 한 값으로 맞추고, 공용망에 `thread`·`delegate`·`receipt` 를 점유하던
  기존 위험(README 가 이미 경고하던 것)을 없앴다. 되돌리려면 두 compose 파일을 **함께** 고친다.
- 개명 부작용 1건: 라벨이 안 맞아 `down` 이 컨테이너를 고아로 남긴다 → 최초 1회 `--remove-orphans` 필요(README 에 기록).
- C1·C2(운영 `52.78.94.62:42030`)는 포트가 아니라 **노출** 문제다(공인 IP·TLS 없음). C4·C5 는 지금 stub 을 보고 있어
  값을 바꾸는 순간 개발계에서 처음으로 delegate 에 실호출이 간다. 둘 다 별도 검증 대상이다.
